# strategies/resonance/web — page template for one symbol's judgement

> **Agents: follow the English part only (above the "中文版" divider). The Chinese part is a translation for human readers and adds no instructions.**
>
> **说明：agent 执行时只需参考上半部分的英文；下半部分的中文仅供人类阅读，内容相同，不含额外指令。**

## What this is

A web page that shows one symbol's major-timeframe judgement from the first model call to the decision: the path the debate took, every call on a real time axis, what each prompt was made of and what came back, every argument with its exchanges and ruling, and the files the run left.

The template holds no data. Every `cli judge` (and `cli report`) writes the data next to the other run outputs, and the page reads it:

```
strategies/resonance/runs/index.json                          pack dates and symbols that have a flow
strategies/resonance/runs/<pack_date>/<symbol>/flow.json      one symbol's flow
```

So after a run there is nothing to do here: reload the page and pick the new pack date.

The project uses the same toolchain as `third_party/quant_trading/web/frontend` (Vite, Vue 3 single-file components, TypeScript, UnoCSS with the same `uno.config.ts` theme and the same CSS tokens), so the components can be moved into that frontend unchanged.

## Files

| File | Purpose |
|---|---|
| `src/types.ts` | The data contract (`FlowData`, `FlowIndex`), the TypeScript mirror of what `strategies/resonance/flow.py` writes. `FLOW_SCHEMA` must equal the one in `flow.py`. |
| `src/api.ts` | `fetchIndex()` / `fetchFlow(packDate, symbol)`. The base URL is `runs` next to the page, or `VITE_FLOW_BASE` when set at build time. |
| `src/views/resonance/DebateFlowView.vue` | The page for one flow. Takes a `FlowData` prop and nothing else. |
| `src/views/resonance/*.vue` | Its parts: `FlowHeader`, `FlowPath` (rounds held and who ended the debate), `CallTimeline` (calls on a time axis), `StepList`, `StepDetail`, `ThreadBoard`, `ThreadCard`, `OutcomeCards`, `FileTable`, and small pieces (`RoleDot`, `RoleChip`, `TagPill`, `VerdictPill`, `EvidenceRefs`, `FactItem`, `SectionHead`). |
| `src/views/resonance/roles.ts` | Role colors and names, formatting helpers. |
| `src/App.vue` | Standalone shell: pack-date and symbol picker driven by `index.json`, selection kept in the URL hash (`#2026-09-30/LC`). |
| `src/style.css` | Design tokens and page defaults copied from the frontend's `style.css`. Nothing else goes here. |
| `uno.config.ts` | The frontend's UnoCSS theme, copied. |
| `tests/render.test.ts` | Renders the page to HTML for the sample flow (every call selected, every thread opened, a run without per-call records) and for every real `flow.json` under `runs/`. |
| `tests/fixtures/flow.sample.json` | A three-round sample flow generated by the judge's own code with the fake runner. Regenerate with `uv run python -m strategies.resonance.tests.make_web_fixture`. |

## Commands

Node comes from the repository's pixi environment; run everything from the repository root.

```sh
pixi run web-install                                # once: npm install into web/node_modules
pixi run web-build                                  # type-check and build into web/dist; rerun after changing the template
uv run python -m strategies.resonance.cli web       # serve web/dist and the flow files at http://127.0.0.1:8770/
pixi run web-test                                   # render tests
pixi run web-dev                                    # live-reload dev server; needs `cli web` running for the data
```

`cli web` serves only `index.json` and `flow.json` files from `runs/`; prompts, raw responses and decision caches are not reachable through it.

The runs directory is `strategies/resonance/runs` unless `--runs-dir DIR` says otherwise. `judge` and `report` write there and `web` reads there, so give all three the same `DIR`. The page itself always asks for `runs/…` relative to its own address; the server maps that to the directory.

## Changing the data contract

`flow.py` (`build_flow`) and `src/types.ts` describe the same object. When a field is added, renamed or removed:

1. Change `build_flow` and bump `FLOW_SCHEMA` in `flow.py` and in `src/types.ts` if existing files become unreadable.
2. Run `uv run pytest strategies/resonance/tests -q`. `test_web_fixture_matches_the_contract` fails while the sample flow has the old shape; regenerate it with `uv run python -m strategies.resonance.tests.make_web_fixture`.
3. Update `src/types.ts` and the components, then `pixi run web-build` (type-check) and `pixi run web-test`.
4. Regenerate the flow files of existing runs with `uv run python -m strategies.resonance.cli report --pack-date <date>`.

## Conventions

- Styling is UnoCSS utility classes in the templates. No `<style>` blocks and no new rules in `style.css`.
- The components assume no CSS reset, because the target frontend has none: margins are zeroed with `m-0`, every border names its style (`border-solid`, `border-t-solid`), and clickable elements are `role="button"` elements rather than `<button>`.
- 多方 is `up` (red) and 空方 is `down` (green), the convention of the trading UI; 主持人 is `warning`, Manager is `primary`. Red and green are hard to tell apart for color-blind readers (the two tokens measure ΔE 5.0 under deuteranopia), so who is speaking is always also written in text.
- Text in the page is Chinese; identifiers, comments and this English part are English.

## Moving it into the trading frontend

1. Copy `src/views/resonance/` into `third_party/quant_trading/web/frontend/src/views/` and merge `src/types.ts` into that app's `types.ts`.
2. Add the two fetch functions of `src/api.ts` to that app's `api.ts`, pointing at an endpoint of its server.
3. In its `server.py`, serve `index.json` and `<pack_date>/<symbol>/flow.json` from the runs directory (`strategies/resonance/serve.py` shows the allow-list).
4. Add a route in its `App.vue` that loads a flow and renders `<DebateFlowView :flow="flow" />`; the picker of this project's `App.vue` can be reused or replaced by that app's own navigation.

# 中文版（仅供人类阅读；agent 请参考上方英文）

## 这是什么

一个网页，展示一个品种的大周期判断从第一次模型调用到决策的全过程：辩论走过的路径、按真实时间排列的每次调用、每个提示词由什么组成以及返回了什么、每条论据的交锋与裁定，以及这次运行留下的文件。

模板本身不含数据。每次 `cli judge`（以及 `cli report`）会把数据写在其他运行产出旁边，页面读取它：

```
strategies/resonance/runs/index.json                          有 flow 的包日期与品种
strategies/resonance/runs/<包日期>/<品种>/flow.json             一个品种的 flow
```

所以跑完之后这里什么都不用做：刷新页面，选新的包日期即可。

工程使用与 `third_party/quant_trading/web/frontend` 相同的工具链（Vite、Vue 3 单文件组件、TypeScript、UnoCSS，`uno.config.ts` 的主题和 CSS 变量都一致），组件可以原样搬进那个前端。

## 文件

| 文件 | 作用 |
|---|---|
| `src/types.ts` | 数据约定（`FlowData`、`FlowIndex`），是 `strategies/resonance/flow.py` 输出的 TypeScript 对应。`FLOW_SCHEMA` 必须与 `flow.py` 里的一致。 |
| `src/api.ts` | `fetchIndex()` / `fetchFlow(packDate, symbol)`。数据地址默认是页面旁边的 `runs`，构建时设置 `VITE_FLOW_BASE` 可改。 |
| `src/views/resonance/DebateFlowView.vue` | 展示一份 flow 的页面。只接收一个 `FlowData` 属性。 |
| `src/views/resonance/*.vue` | 它的各个部分：`FlowHeader`、`FlowPath`（打了几轮、谁终止了辩论）、`CallTimeline`（时间轴上的调用）、`StepList`、`StepDetail`、`ThreadBoard`、`ThreadCard`、`OutcomeCards`、`FileTable`，以及小部件（`RoleDot`、`RoleChip`、`TagPill`、`VerdictPill`、`EvidenceRefs`、`FactItem`、`SectionHead`）。 |
| `src/views/resonance/roles.ts` | 角色的颜色与名称、格式化辅助函数。 |
| `src/App.vue` | 独立运行时的外壳：由 `index.json` 驱动的包日期与品种切换，选择保存在 URL 的 hash 里（`#2026-09-30/LC`）。 |
| `src/style.css` | 从前端的 `style.css` 拷贝的颜色变量和页面默认样式。这里不放别的。 |
| `uno.config.ts` | 拷贝自前端的 UnoCSS 主题。 |
| `tests/render.test.ts` | 把页面渲染成 HTML：样例 flow（逐个选中每次调用、逐个展开每个线程、没有逐次留痕的运行），以及 `runs/` 下每一份真实的 `flow.json`。 |
| `tests/fixtures/flow.sample.json` | 由判断层自己的代码配合假运行器生成的三轮样例 flow。用 `uv run python -m strategies.resonance.tests.make_web_fixture` 重新生成。 |

## 命令

node 来自仓库的 pixi 环境；所有命令在仓库根目录执行。

```sh
pixi run web-install                                # 一次性：把 npm 依赖装到 web/node_modules
pixi run web-build                                  # 类型检查并构建到 web/dist；改了模板后重新执行
uv run python -m strategies.resonance.cli web       # 在 http://127.0.0.1:8770/ 提供 web/dist 和 flow 数据
pixi run web-test                                   # 渲染测试
pixi run web-dev                                    # 热更新开发服务；数据需要 `cli web` 同时在运行
```

`cli web` 只对外提供 `runs/` 里的 `index.json` 和 `flow.json`；提示词、原始响应和决策缓存无法通过它访问。

runs 目录默认是 `strategies/resonance/runs`，用 `--runs-dir 目录` 可以换。`judge` 和 `report` 往这里写，`web` 从这里读，所以三个命令要传同一个目录。页面本身始终请求相对自身地址的 `runs/…`，由服务把它映射到该目录。

## 修改数据约定

`flow.py`（`build_flow`）和 `src/types.ts` 描述的是同一个对象。增加、改名或删除字段时：

1. 修改 `build_flow`；如果旧文件因此无法读取，同时提高 `flow.py` 和 `src/types.ts` 里的 `FLOW_SCHEMA`。
2. 运行 `uv run pytest strategies/resonance/tests -q`。样例 flow 仍是旧形状时 `test_web_fixture_matches_the_contract` 会失败；用 `uv run python -m strategies.resonance.tests.make_web_fixture` 重新生成。
3. 更新 `src/types.ts` 和组件，然后 `pixi run web-build`（类型检查）和 `pixi run web-test`。
4. 用 `uv run python -m strategies.resonance.cli report --pack-date <日期>` 重新生成已有运行的 flow 文件。

## 约定

- 样式一律用模板里的 UnoCSS 工具类。不写 `<style>` 块，也不往 `style.css` 里加规则。
- 组件不依赖 CSS reset，因为目标前端没有 reset：外边距用 `m-0` 归零，每条边框都写明线型（`border-solid`、`border-t-solid`），可点击的元素用 `role="button"` 的普通元素而不是 `<button>`。
- 多方用 `up`（红），空方用 `down`（绿），与交易界面的习惯一致；主持人用 `warning`，Manager 用 `primary`。红绿对色觉障碍读者难以区分（这两个颜色在绿色盲模拟下的色差只有 5.0），所以"谁在说话"总是同时用文字写出来。
- 页面文字用中文；标识符、注释和本文件的英文部分用英文。

## 搬进交易前端

1. 把 `src/views/resonance/` 拷到 `third_party/quant_trading/web/frontend/src/views/`，把 `src/types.ts` 并入那个应用的 `types.ts`。
2. 把 `src/api.ts` 的两个读取函数加到那个应用的 `api.ts`，指向它服务端的接口。
3. 在它的 `server.py` 里从 runs 目录提供 `index.json` 和 `<包日期>/<品种>/flow.json`（放行规则见 `strategies/resonance/serve.py`）。
4. 在它的 `App.vue` 里加一个路由，读取 flow 并渲染 `<DebateFlowView :flow="flow" />`；本工程 `App.vue` 里的切换器可以沿用，也可以换成那个应用自己的导航。
